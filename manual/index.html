伙伴看板从上到下、从左到右分为四块：

2.2 怎么看

  1. 先看 4 张快速摘要卡：整页头部并排 4 张（整体进度 · 本周活动 · 下次活动 · 未完成待办），每张都是可点击的快捷入口——点哪张直接跳到对应 tab 或活动详情。
  2. 看活动：进入「活动看板」Tab，点「全部展开」看全部活动，或点某个板块只展开该社群；用顶部搜索框输入活动名/社群/导师快速定位。
  3. 看排期：切到「日历视图」Tab，看每个月的活动密度，跨天活动会横向拉长。
  4. 看要交给街道的东西：切到「街道交付」Tab，看三类交付物（活动反馈 / 视频 / 推文）的责任人、约定提交时间与真实完成情况；未填完成情况的才按约定日期提醒，优先处理「已逾期」「7 天内」。
  5. 看自己要做的事：切到「待办事项」Tab，看分档预警——优先处理「已逾期」「3天内」的事项。
  6. 登记随时：两处登记入口固定在 H1 下方横幅区（活动反馈问卷 + 登记待办），KPI 卡下方还有一行「登记待办」快捷 CTA，不必切来切去找入口。
一句话说明：这个看板只展示活动安排和你的待办，专注项目内容本身，可以放心转发给内部伙伴与合作方。

四、要登记什么：两类必登事项

内部人员日常要在两个入口登记，缺一不可。

登记项入口谁登记时机
① 活动反馈 腾讯问卷（伙伴看板顶部横幅 / 伙伴看板「填写活动反馈」） 每场活动的执行老师 / 主理人 每场活动结束后当天
② 待办事项 腾讯文档智能表「待办事项」台账 各事项的责任人 产生待办时登记、完成时更新状态

五、怎么登记：活动反馈问卷

入口：https://wj.qq.com/s2/27647616/pg6d/（伙伴看板顶部横幅「填写活动反馈 ↗」直达）

5.1 什么时候填

每场活动结束后当天填写提交。不要拖到第二天，否则「三件套」里的现场信息容易遗漏。

5.2 必须提交的「三件套」

① 签到表 必填
参加活动人员的签到记录（照片或文件）
② 活动照片 必填
现场活动照片（清晰、能反映活动开展情况）
③ 现场小结 必填
本场活动的简要文字小结（做了什么、效果如何）

以上三件套缺一不可，问卷填写时请特别注意提交完整性。

5.3 填写步骤

  1. 打开伙伴看板，点顶部横幅右侧「填写活动反馈 ↗」。
  2. 按问卷提示填写本场活动信息（活动名称、社群、日期等）。
  3. 上传「三件套」：签到表、活动照片、现场小结。
  4. 检查无误后提交。
红线：「三件套」任缺一件即视为提交不完整，需退回补交。这是活动台账与结项材料的关键依据，务必当日完成。

六、怎么登记：待办事项台账

入口：https://docs.qq.com/smartsheet/DRkJvbE9yY1h1cmxN（伙伴看板「➕ 登记待办」直达）

6.1 台账字段说明（共 10 个登记字段）

字段类型是否必填填写说明
事项文本必填一句话说清要做什么，如「联寓公寓沪语课程场地确认」
责任人多选必填谁负责这件事，可多选
截止时间日期必填到期日期，看板据此自动分档预警
关联方多选必填内部 / 授课老师 / 街道 / 居民区书记 / 社群主理人 / 场地方（决定这条待办分流到哪个视角）
关联对象文本选填具体对接的人，如「黄老师（街道）」
关联活动关联选填关联到具体某场活动
类型单选选填如「沟通确认」等分类
优先级单选选填高 / 中 / 低
状态单选必填未启动 / 进行中 / 已完成（完成时务必改状态）
跟进摘要文本选填记录跟进过程，便于交接

7 天截止3 < 距截止 ≤ 7 天临近

6.3 登记步骤

  1. 打开伙伴看板，点「➕ 登记待办 ↗」直达腾讯文档台账。
  2. 点「新增记录」，逐项填写：事项、责任人、截止时间、关联方、状态（至少这 5 项）。
  3. 如有对接人、关联活动，补填「关联对象」「关联活动」。
  4. 事项完成后，把「状态」改为已完成，该条会自动归档到「已完成」分档。
关联方的作用：待办台账里的「关联方」字段，决定这条待办会分流到哪个视角展示（内部 / 授课老师 / 街道 / 居民区书记 / 社群主理人 / 场地方）。填的时候务必选对，才能让该看到的人看到、该跟进的跟进。

七、三件套与数据闭环规则

7.1 数据从哪来、到哪去

数据源流向
《项目进度融合跟进表 V5》Excel→ 活动 / 方案 / 主理人 / SOP 数据 → 伙伴看板、课程计划看板
腾讯问卷（活动反馈）→ 活动执行留痕（反馈记录，作为结项材料）
腾讯文档「待办事项」台账→ 待办分档预警 → 伙伴看板（按关联方分流）

7.2 闭环铁律

  • 当日反馈：活动结束当天提交问卷 + 三件套。
  • 即时登记：有新的待办，第一时间进台账登记。
  • 完成即改：待办做完，立刻把状态改为「已完成」，否则会一直挂着触发预警。
  • 选对关联方：待办的「关联方」选错，会导致该条分流到错误的视角（比如内部事项误归到街道）。

八、给街道的纸质交付：街道看板「导出打印版」

链接：/leader/ ｜ 用途：把活动执行台账导出成 A4 打印版，直接打印，或另存为 PDF 后交付 / 存档给街道。

8.1 三步操作

  1. 先筛范围：在街道看板顶部用「月份 / 日期」筛选到要交付的区间（不筛选 = 项目全周期）。
  2. 点「导出打印版」：页面顶部「📄 交付街道」那一行，点右侧按钮，弹窗里勾选要包含的内容（见 8.2）。
  3. 打印或存 PDF：点「生成并打印」后会打开新窗口并自动唤起打印对话框 → 选「目标打印机 → 另存为 PDF」即得到可交付的 PDF；也可直接连打印机打印。

8.2 可以打印什么（勾选项）

内容默认说明
活动明细台账✅ 开逐场一张卡片（与看板同格式）：日期 / 活动名称 / 归属 / 形式 / 地点 / 负责人 / 参与人数 / 活动主题与小结。小结独立成块、整幅宽度，不再挤在表格单元格里
开展情况汇总✅ 开按归属社群统计场次、参与人次、日期区间，末行自动合计
街道相关待办⬜ 关只看「关联方 = 街道」的待办，含截止时间、责任人、状态
现场照片（跟在每场活动下方）⬜ 关签到表 + 活动现场照片，直接排在该场活动卡片的小结之下（不再单设照片附录章节）；可选每场最多 3 / 6 张或全部；按原图实际比例展示、不裁剪（旧版固定 3:4 竖版会把照片截掉，已改）

8.3 打印版长什么样

  • A4 纵向，表格排版、自动分页，跨页时表头自动重复，同一场活动不会被拆到两页。
  • 抬头固定带：项目名、「主办单位：黄浦区老西门街道办事处 ｜ 承办单位：天韵公益服务中心」。
  • 元信息区：统计范围、活动周期、活动场次、参与人次、覆盖社群、导出时间。
  • 文末签署栏：编制单位 / 编制人 / 报送日期 / 街道接收确认，可直接手写签字。
  • 每页页脚带项目名与导出版本号（与看板 BUILD_VER 一致），便于核对是哪一版数据。
口径说明：打印版与线上看板同源同筛选——看板上筛完是什么，打出来就是什么；数据来自已开展活动台账（含前期社群评估设计）。若打印出来是空的，多半是筛选范围没有匹配到活动，点「清除筛选」后重试。
交付建议：给街道的正式交付，建议用「另存为 PDF」而不是直接打印——PDF 体积小、可微信发送、可存档留痕，且版式不会因对方打印机不同而变。

8.4 两种分类口径：按社群 / 按费用分类

街道看板顶部新增「分类口径」切换条，两种口径共用同一份数据与同一个月份/日期筛选，切口径不丢筛选：

口径一级分组二级适合
按社群（默认）五大社群 + 整体社群—日常看活动落在哪个社群、社群孵化进展
按费用分类V5 服务购买预算明细四大类（一、社群矩阵搭建 / 二、社群种子招募 / 三、社群孵化活动 / 四、社群项目支持与反哺）+ 机制建设 + 品牌输出（共 6 组；非服务购买不在看板呈现）费用细项（服务购买 23 项，逐项列出）；「三、社群孵化活动」再按 5 大社群展开，社群下才是费用细项按预算科目口径汇报、核对"钱对应的活动做了没有"
  • 分类与细项名称直接取自 V5 权威表（「服务购买预算明细」sheet），看板与 V5 始终对齐，不手工维护第二套分类。非服务购买不进看板。
  • 三层结构：费用分类 → 费用细项 → 活动卡片；「三、社群孵化活动」为四层：费用分类 → 5 大社群 → 费用细项 → 活动卡片。
  • 细项归哪个社群由 V5 决定：取该细项对应计划行的「关联社群」字段（如 · 沪语学堂 → 吴侬软语坊、· 中医非遗课 → 杏林守艺堂、· 非遗手工课 → 指尖温度圈）。跨社群的细项（如 · 社群主理人赋能）与暂无计划行的细项，统一进「跨社群 / 待确认」组。
  • 活动如何挂到细项：按关键词规则自动挂靠（如「沪语」→ · 沪语学堂、「非遗手作」→ · 非遗手工课、「评估」→ 社群评估与适配方案设计）。
  • 遇到挂不上的，不硬塞也不丢：进「其他（未挂细项）」，并在该条下提示「该科目下有 N 项待归类计划」，逐条与项目组确认后再落到具体费用细项（目标：所有内容最终都归到四大费用分类内）。
  • 每组显示「已开展 N 场 · 计划 M 项」：M 是该科目/社群下的计划工作量，便于街道看到科目全貌与推进度。
  • 未开展的分类/细项/社群保留占位「暂未开展」：预算科目与社群骨架完整，不因暂无活动而消失。
  • 本口径不展示任何金额——只呈现结构与开展情况（预算金额、已支出属内部台账，不进街道看板与打印件）。

8.5 打印导出会跟随当前口径

  • 在「按社群」下导出 → 汇总表按社群，明细台账同样为卡片式并按社群分组（与看板一致）。
  • 面向街道的表述口径：不显示「计划时间进度」与「计划」两列等易被误读的指标，只保留 应完成 / 已完成 / 按期完成率；表下的「口径说明」整段不再输出（不再出现「项目全周期约定量」「本表不含金额」等解释性文字），全篇不出现看板系统名称与内部术语。
  • 在「按费用分类」下导出 → 汇总表为「活动开展情况汇总（按费用分类）」，6 列：费用分类 / 已开展的活动·费用细项 / 应完成 / 已完成 / 按期完成率 / 参与人次（含合计行）。三类只呈现一条汇总行，不再展开社群小类；三类在明细台账中仍按 5 大社群分组（每场一张卡片，meta 标注费用分类与费用细项）。文档标题标注「（按费用分类）」，且全表不含金额。
  • 打印面板会显示「分类口径：按社群 / 按费用分类（跟随看板当前口径）」——想打哪种口径，先在看板上切好再点导出。
